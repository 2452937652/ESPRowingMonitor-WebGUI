- session JSON：41 个不同 V2 桨键，桨频和每桨距离全部为 0；41 桨速度、拉桨时间、物理曲线和长度非零；40 桨有完成的恢复/功率/阻力数据，最后一桨仍 pending。
- session CSV：同样 41 桨，桨频和每桨距离全为 0；40 行速度也为 0。旧 CSV 以桨频乘以每桨距离重新计算速度，与已有 JSON 速度不一致。
- FIT：完整性检查通过、解码无错误、41 条记录；总距离 114.15 m、总桨数 41、平均/最大桨频和平均桨距均为 0。速度却与 JSON 的有效速度一致，证明问题不只出在 CSV。
- deltaTimes JSON 与 CSV：10,244 个脉冲间隔逐项相同，总计 125.666229 秒。这两份不是 BLE 消息时间线，无法还原每次界面更新或单凭这些数据精确补回丢失指标。

## 改动

1. V2 桨边界保存当前和前一桨的固定快照，桨频/桨距不随同一桨的滑行通知或补充包重新变化。速度继续按飞轮更新。
2. 同一个 V2 桨键的会话合并、数据库更新都保留已经测出的非零桨频和桨距，防止后续零值覆盖；新桨/新会话不借用上一桨的数据写入记录。
3. 实时显示在下一桨数据尚未完成时保持最近的拉桨长度、拉桨时间、峰值、桨频和桨距。此保持只作用于显示，不把上桨曲线或数值伪造为新桨记录。
4. V2 同桨滑行时原先更新 rawDistance 基准却不增加会话距离，造成这部分距离被跳过。现在只为活动桨增加该距离一次；暂停移动和历史补充包不增加距离。
5. CSV 直接使用已经保存的速度，与 JSON/FIT 一致。旧文件缺少有效 speed 时才使用兼容计算。
6. 设置页显示修订号 20260926.2，JSON 包含 exportedBy，标识导出网页版本（不冒充录制时的版本）。

未改写原始附件，也未把旧文件中的零桨频/桨距估算值冒充实测值。没有修改固件、物理参数或 NVS。
